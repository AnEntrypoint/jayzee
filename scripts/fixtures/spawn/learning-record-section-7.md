## 7. Error keys on world-store (scoped observation)

Re-witnessed in the audit (one GET each, `curl -sS -m 15`, base `https://play.spawn.co/world-store`):

- `value_not_found`, condition: absent hash. `GET /values/<64 zeros>` → 404 application/json, 27 bytes, `{"error":"value_not_found"}`. `GET /values/<64 f>` → 404 application/json, 27 bytes, same body. `GET /manifests/<64 zeros>` → 404 application/json, 101 bytes, `{"error":"value_not_found","hash":"0000…0"}`. `GET /manifests/<64 f>` → 404 application/json, 101 bytes, same shape with the `f` hash echoed. Present controls: `GET /values/3fa9a434…` → 200 application/octet-stream, 1266 bytes; `GET /manifests/5a526ee6…` → 200 application/octet-stream, 513116 bytes. Scoped reading: two absent 64-hex hashes return `value_not_found` on both paths, so the key is not specific to the all-zero hash. Two absent hashes tested; this is not a rule for all absent hashes.
- `unknown_world_store_key`, REPRODUCED once by a path-level probe. Class: a valid 32-hex world uuid with a non-existent resource name. `GET https://play.spawn.co/world-store/git/41cd46499614484ca9261ce32e257e22/head.jsn` → 404 application/json, 35 bytes, `{"error":"unknown_world_store_key"}`. Its control, same world, correct name: `GET …/41cd46499614484ca9261ce32e257e22/head.json` → 200 application/json, 1673 bytes, with `"manifest":"3fa9a434…"`. One request each, one class. Scoped reading: a misspelled resource under a known world gives `unknown_world_store_key`. The original savi case (drifted head, manifest 3fa9a434…) is still NOT reproduced, so the condition for that case is OPEN. Do not generalise from one request.
