# AGENTS.md

Non-obvious facts for automated edits. Architecture and measured costs live in docs/ARCHITECTURE.md.

## Rules

- Source files carry no comments. Put a fact the code cannot express here, after checking it is still true.
- Kernel files in src/kernel use only the numeric subset jz accepts: typed arrays, numbers and loops. No objects, closures or classes. The buffers are module bindings in `src/kernel/state.js`, allocated once by `reserve`, and no other kernel function allocates. A kernel function that takes a typed array as a parameter is compiled on jz's dynamic path whenever another kernel function calls it, so the buffers are never passed as arguments.
- Edit source, never dist/. `npm test` rebuilds dist/kernel.wasm before the suites run.
- A kernel signature change touches `src/kernel/step.js`, `src/kernel/load.js`, `src/world/World.js` and `scripts/check-kernel.mjs` together. `step` passes its arguments positionally.
- Keep `MODULES` in `src/kernel/build.js` in step with the imports. A missing file fails the build with an unresolved import.
- Hygiene scans (comment markers, bare imports, host globals) live only in `scripts/check-hygiene.mjs`. A source directory that needs them joins its `SCOPES` table, not a per-file gate.
- scripts/lib/gate.mjs holds the shared PASS and FAIL reporter. A new gate imports it, runs each claim through gate(label, fn), and ends with finish().
  A gate body may return a promise. Its PASS or FAIL line prints when the promise settles, and `finish()` prints RESULT after every pending gate. Before this, `gate` ran an async body without awaiting it, so PASS printed before its assertions ran.

## Working loop

- A change is proved by the one check that can fail for it. Run that check alone: `npm test -- <name or path fragment>` runs every chain entry whose name or command contains the fragment, so `npm test -- scenario` runs the scenario gates and `npm test -- check-ccd.mjs` runs one file. `npm test -- --list <fragment>` prints what would run.
- A failing check is rerun alone, by name. The runner prints the command.
- `npm test` with no fragment runs once, before the push. Do not run it to see whether a narrow change broke something unrelated.
- A check that passed on a tree is not run again on that tree. The runner keeps the passes per tree in `build/checks/passed.json` and skips them. The tree key covers every tracked and untracked file except `docs/PENDING_VALIDATION.md` and `docs/CHECK_TIMES.md`, plus the names, sizes and times of `engine/out`. `npm run test:force` ignores the record.
- `scripts/build-kernel.mjs` rebuilds `dist/kernel.wasm` only when `src/kernel` or the jz package changed (`dist/kernel.wasm.inputs` holds the digest). `--force` rebuilds.
- Checks run `--jobs` at a time (default 4, or `CHECK_JOBS`). A check that measures time or allocation goes in `scripts/test-serial.json` and runs alone after the others.
- Each check writes its output to `build/checks/<name>.log` and its wall time to `build/checks/timings.json`. `docs/CHECK_TIMES.md` records the times; a check over 2 s needs a reason there.
- A hunt, build or long run is started once and waited on in the same turn, by its process, with a bounded timeout. Do not sleep and do not poll it. Do other Phase A work while it runs, and do not end the turn while it is running.
- A browser witness is run when the change can alter what the browser does. A runner-only change is proved by the gate that reads the runner.

## Facts that bite

- `World#hash` is FNV-1a over the float64 bit patterns, read as uint32 words in JavaScript. It is not in the kernel. A negative zero and a positive zero hash differently.
- `resolvePairs` records each body's cell from positions at the start of the call. A body that moves into another cell mid-pass is searched in its recorded cell until the next call. Solver iterations close the gap.
- The cell filter in `resolvePairs` is what keeps a bucket collision from duplicating a pair. Remove it and pairs are counted twice whenever two neighbour offsets share a bucket. The bucket-collision test guards this.
- `cells` holds three int32 per body. `head` and the occupancy bitset `occupied` must each be a power of two long, because the pair search masks its hash; `instantiateKernel` refuses any other size. `World` sizes `head` to the power of two at or above two buckets per body, with a minimum of 64, and `occupied` to a quarter as many words, which is eight bits per bucket.
- The bucket hash in `resolvePairs` is free to change: a bucket chain is always in descending body index and the cell filter decides membership, so the hash changes which probes are wasted and never which pairs are resolved or in what order. The gate that runs one bucket against 4096 holds that bit for bit. The occupancy bitset answers most of the 27 neighbour probes of a body without touching `head`.
- An index or a value read from an Int32Array is typed as an integer by jz only with a `| 0` on it. Without it the pair search runs on float64 with a conversion per access (0.6 ms a step at 500 bodies against 1.3 ms). The cell is stored first and read back with `| 0`, so a coordinate past 2^31 cells wraps as the typed array wraps it.
- `RESTING_SPEED` in `src/kernel/respond.js` is 1 m/s. Impacts slower than that cancel the normal velocity instead of bouncing. Changing it changes what counts as resting.
- `World#advance` caps catch-up at 8 ticks. Time past that cap is dropped on purpose.
- Each `World` owns a wasm instance. Its memory is released only when the world is garbage collected, so a long-running process should drop worlds it no longer uses.
- A typed-array access in the compiled kernel costs under 1 ns. The 15 to 25 ns recorded before was jz's dynamic path: every array was a parameter, so each access was a hash lookup, and the module carried the dynamic runtime (131,666 bytes against 16,460 now, with no host import). `check:kernel` fails when the kernel has an import or passes 32,768 bytes, which is how a return to that path shows. `jz --why` on `src/kernel/kernel.js` names the accesses it could not type.
- The kernel is compiled with `optimize: { level: 'speed', compact: false }`. The size level is 6,832 bytes and 3.3 times slower a step. Compaction is off because nothing is allocated after `reserve`.
- The package needs Node 22 or newer. `.nvmrc` pins 24.
- Commit as lanmower, with no trailers, under the owner rule in CLAUDE.md.
- `Authority` takes one input per player per tick, so `InputBuffer.next` must equal the world tick plus one. Add every player before the first `step`; a player added later starts at sequence 1 and falls out of step.
- `Predictor#predict` defaults `buttons` to 0. The sequence it assigns is the world tick plus one, so predict only once per tick.
- `Predictor#reconcile` keeps unacknowledged inputs until a state covers them. Under sustained loss the pending list grows with the gap between acknowledgements.
- The netcode witness uses one seeded generator for intents, loss and delay. Changing the order of random draws changes its numbers, not its verdict. The 4-tick control is expected to show gaps and must keep doing so, or the witness no longer tests what it claims.
- Redundancy works only up to the playout delay. Each input has `delay + 1` chances before its playout time, so raising the redundancy above that buys nothing.
- `World#importState` resets the accumulator, so a restore partway through a fixed step drops that remainder on purpose.
- `decodeDelta` compares a base by tick and body count. `StateSender` and `StateReceiver` both keep 64 states by tick. The receiver keeps every state the sender can still use as a base, because the sender only uses an acknowledged tick within its own 64-tick history. Changing one depth without the other breaks that guarantee.
- Bodies are compared with `Object.is`, so a −0 change is a real change and is sent. A body that jitters between two bit patterns is sent every tick, which costs bytes but not correctness.
- `manifest.bin` in a spawn world is a run of frames, each a big-endian uint32 length followed by its payload, and the frames end exactly at the file's end. Frame 0 is the index `{v, hashes}` and `hashes` is an object whose values are the 80 value hashes. Frame 1 is the sheet, and its sha256 equals `head.sheet`. Frames after the sheet are checked by `bindFrames`, which requires frame k+1 to hash to `hashes[k]` in order. `decodeFrame` inflates a gzip frame and names its body as a file map, a summary, a leaf map or other. None of the hashes inside those frames is an index hash, so their content is parsed, not verified. The fixture manifest binds its three frames, and the exception manifest `d048ad…` has a non-JSON third frame that matches no index hash.
- Spawn ledger names use `~XX` hex escapes (`~2f` is `/`, `~3a` is `:`). `decodeName` throws on a bare tilde or a non-ASCII escape. `encodeName` escapes each UTF-8 byte outside `a-z 0-9 . - _` as `~XX`, as the upstream probe test does (its encoder-test.mjs lines 12 and 13), so `:` is `~3a`, `~` is `~7e`, and capitals are escaped. Captured keys use only `~2f`. `~7e` and non-ASCII escapes come from upstream's client code, not from a captured key. `decodeName` still refuses non-ASCII escapes.
- `resolve-found.json` is spawn's resolve response, reported by the spawn agent and not captured from the probe. `found` and `not_found` are parsed. `not_found` is `resolve-not-found.json`, a live response reported by the spawn agent. `redirect` is captured as HTTP 307 from the apex host and 308 for a trailing slash or http, each with the body `Redirecting...` and a `Location`, and `classifyResolve` returns it. The upstream OpenAPI spec documents only HTTP 200 and 400 for this route. Its 200 body carries `result.type` values `found`, `redirect` (a renamed world, parsed as `renamed` with `newAdventureName`), `gone` (a deleted world, parsed with `appName`, `username`, `adventureName` and `deletedAt`) and `not_found`. A status 410 is therefore refused as undocumented; `gone` is never an HTTP status. The `gone` and `renamed` fields are the spec's required fields, not captured bodies.
- `src/protocol/messages.js` mirrors spoint's `src/protocol/MessageTypes.js` at d5e3860: 105 ids and 12 unreliable names. `scripts/fixtures/spoint-messages.json` is generated by importing that spoint module, not written by hand. Several ids are declared but unused in spoint (for example `DELTA_UPDATE` and `PLAYER_JOIN`), and they are kept so the id space matches.
- A missing head is a 404 with `{"error":"head_not_found"}`. Any other non-200 status is an error.
- A ledger key is `world.assets/<2 hex>/<encoded>.yaml`. The bucket is the top byte of FNV-1a over the UTF-16 code units of the asset name (`ledgerBucket`), and `parseLedgerKey` refuses a key whose bucket is not the derived one. Two full keys quoted in upstream's text reproduce, and a 307-key census outside this repo matched.
- The feed walk is offset-based: 22-entry steps, a 44-entry page cap, and it stops after two empty pages. Repeated worlds are dropped.
- `scripts/fixtures/spawn` is trimmed from the spawn probe scan `4e709464ecfc408f980ac3b5b46b0ee3` and its feed listing of 2848 entries, which were not recorded in this repo. The gate reads only the fixtures.
- `src/fire/fireKernel.js` ports spoint's `src/shared/fire/fireKernel.js` at d5e3860 without its HMR hooks. spoint's `createFireLattice` and its `cubeFaceOf` import from `terrain/PlacementLattice.js` are not ported. The kernel takes any lattice with `walk`, `cellsPerFace`, `faceCount` and `windInFaceAxes`.
- The fire hash is `cellHash` in `src/fire/fireKernel.js`. It is a murmur-style integer mix over the seed, step, face, I and J, masked to 24 bits, and it is not FNV. The spot roll reads the low 16 bits, the spot distance bits 16 and 17, the lateral offset bits 20 and 21, and rain reads the low 8 bits. `checksum()` folds per-cell hashes by sum (int32) and xor (uint32) and returns a uint32.
- `seed` goes through `^`, so it is coerced to int32. A seed of 2^32 + 1 is the same as seed 1.
- A tile is 8 by 8 cells (`TILE_AXIS_CELLS` is 8, 64 cells). Its activity and interior masks are Uint32 words, with cells 0 to 31 in the low word and 32 to 63 in the high word. Bit 31 is set in those words, so they must stay unsigned.
- Cell widths: `state` and `cls` are Uint8, and `fuel`, `heat` and `timer` are Uint16. `addHeat` clamps heat to 65535, and `timer` holds `stepIndex & 0xffff`, so it wraps every 65536 steps. `tileFace` is Uint8 and `FACE_FREE` (255) marks a freed tile, so a lattice face index must stay below 255. Class parameters are Uint16, except `smoke`, which is Uint8 and wraps silently above 255.
- Heat moves as `(heatOut * weight) >> 8`, where each weight is an Int32 clamped to [4, 255]. `rainRoll` is capped at 255, so a rain value above 255 behaves like 255.
- `wind` keeps the raw value and the effective wind is clamped to plus or minus 16 (`FIRE_MAX_WIND_COMPONENT`). The snapshot keeps the raw value, so a restore clamps it again.
- `Math.floor(fuelInit * regrowFuelFraction)` is the only non-integer operation. With a fraction below 1, regrown fuel never equals the class fuel, so a regrown tile is never quiet and is never reclaimed.
- The undo log grows until `takeDelta()`. A caller that wants one delta per step must call `takeDelta()` and `releaseDelta()` at each step boundary, or the next `undoDelta` reverts several steps.
- `src/fire/behaviour` takes samplers, the frame and io sinks as arguments and never reads an app context. Callers bind appCtx at the edge.
- The fire lattice walk is symmetric only in the sense that some step from a neighbour returns to the origin. Across a cube edge the step changes axis, so the opposite direction in the new face's coordinates is not the way back.
- The keyframe encoder's `advance(budgetMs)` makes no progress with a budget of 0, because its deadline is reached on entry. Use a positive budget.
- `createFireTimeline#startAt` throws once the timeline has advanced at all, so it must be the first call.
- `createChecksumLedger` applies one `limit` (default 64) to both local history and received remote checksums.
- `IGNITE_AREA` wire rows carry the radius but no source byte, because the kernel does not read one for area ignition.
- `fireQueries.js` uses float arithmetic on purpose. The integer-only rule covers the kernel and the wire, not these queries.
- `src/sandbox/ses.js` does not import SES. `preflightSes` takes an `importSes` function, and when it resolves, locks down with `errorTaming: 'unsafe'`, `stackFiltering: 'verbose'` and `overrideTaming: 'severe'`. A `SES_ALREADY_LOCKED_DOWN` error from lockdown counts as success.
- `preflightSes` returns `ok` or one refusal code: `ses-not-installed`, `lockdown-missing`, `lockdown-failed`, `compartment-missing` or `intrinsics-not-hardened`. A preflight that throws becomes `preflight-threw`. Every refusal fails closed with no Compartment.
- `createSesEvaluator` memoises one preflight. On a refused preflight, `evaluate` throws `SandboxUnavailableError` (code `SANDBOX_UNAVAILABLE`) before the blocklist is read, so a blocked source gets the throw, not null, while SES is unavailable.
- The blocklist is a substring match, so it also rejects the same text inside strings and comments. A blocked or empty source returns null and logs one line, and it does not throw.
- `timingSafeTokenEqual` returns false for non-string input and for tokens with different UTF-8 byte lengths. It uses `node:crypto` `timingSafeEqual` when Node is present.
- `resolveWithinRoot(root, candidate)` returns the resolved path, or null when it lands outside the root. The root itself is accepted, and a sibling that shares the root's prefix is rejected. An absolute candidate is taken as a filesystem path, so a URL path must drop its leading slash first.
- `COEP_VALUE` is `require-corp`.
- The simulated link in `src/transport/simTransport.js` follows spoint's random-draw order. With `reorderPct` above zero a payload can arrive before its own minimum latency, measured at 1011 of 2000 early with latency 20 and no jitter. A minimum-latency claim must run with reorder at zero.
- The anticheat modules in `src/anticheat` take their clock as an argument and throw when it is missing or not finite. Spoint's versions default to `Date.now()`, so a port that drops the argument would make the rate limit and outlier flags depend on wall time.
- `src/sdk/cronSchedule.js` treats a `*/n` day field as restricted, so when both day fields are restricted a time fires on either. Vixie cron uses AND there. spoint has the OR rule, and the port keeps it.
- spoint's `RegionRouter` picks a region by containment with floor arithmetic, not by nearest region. A point on a cell border lands in the upper cell. `src/sharding/RegionRouter.js` keeps that rule.
- `src/client/ClockSync.js` refuses a NaN round trip or receive time, where spoint accepted them. `ReconnectManager` is a plain transition table with its timers and transport injected, and a send error propagates instead of being logged.
- The collision mirror (`src/client/CollisionMirror.js`) steps only a position that `covers` reports as covered, as spoint PredictionEngine does. Its Jolt character manager is `src/collision/characterManager.js`, a port of spoint CharacterManager on CharacterVirtual. Landed heights are float32 from Jolt (1.2999999523 for 1.3), so compare them within a tolerance. `scripts/fixtures/spoint/collision-mirror.json` is written from spoint's own PhysicsWorld by `scripts/gen-collision-mirror-fixture.mjs`, which runs in Node.
- `src/protocol/msgpack.js` packs with msgpackr 2.0.4 under spoint's Packr settings, so its bytes equal spoint's for the 56 fixture values in `scripts/fixtures/spoint/msgpack-cases.json`. Negative zero matches too, without editing node_modules: the released msgpackr writes integer 0 for -0 (its integer branch catches it first), so `pack` packs a copy with each -0 replaced by a non-integer sentinel and then overwrites the sentinel's nine bytes with `cb 80 00 00 00 00 00 00 00`, the bytes spoint's `scripts/patch-deps.mjs` produces. It proceeds only when the sentinel pattern occurs once per -0, and it covers plain objects, arrays and Maps, so a -0 inside a class instance, Date or Set is still packed as 0. `scripts/check-negative-zero.mjs` is the gate. `pack` refuses a function at any depth, where msgpackr would write undefined. Unpacking a top-level 0xc1 is refused. The wire structure hash still matches spoint's value at d5e3860.
- spoint's `LagCompensator` clamps a rewind request older than the window to the oldest retained tick. It does not refuse it. A 5000 ms window retains only 255 ticks, because the sample ring holds 256 entries. `src/netcode/lagCompensation.js` keeps both behaviours.
- `scripts/fixtures/spoint/feature-gap.json` snapshots the counts and names of the spoint report copy. PARITY.md no longer lists them (rows 1 and 61 to 66 were removed for the cross-map), so the snapshot is regenerated with `node scripts/gen-feature-gap.mjs <report>` when the copy changes. The spoint report's 47 checked items are its own claims, and the gate labels them UNVERIFIED.
- Five spoint files declare port 3002: `construct.js`, `deathrun.js`, `tps-game.js`, `tutorial-rpg.js` and `tutorial.js`. `scripts/fixtures/spoint-content.json` records them, and `scripts/check-content.mjs` pins the five. The apps/maps listing has one non-GLB entry, `.glb-cache`.
- msgpackr 2.0.4 is a runtime dependency, pinned exactly to match spoint, and is the packer behind `src/protocol/msgpack.js`. `scripts/check-msgpackr-compat.mjs` reads `scripts/fixtures/spoint/replay-sample.bin`, which `scripts/gen-replay-fixture.mjs` writes from spoint's own `encodeReplay`, and checks that `encodeReplay` reproduces it byte for byte.
- `src/replay/file.js` writes and reads spoint's msgpackr record dialect through `src/protocol/msgpack.js`, byte for byte for `scripts/fixtures/spoint/replay-sample.bin` and the variants in `replay-variants.json`. The format has no checksum, and spoint's ReplayFile has none either, so a flipped payload byte is accepted. `encodeReplay` refuses an undefined field, which spoint would write.
- `src/wire/binSnapshot.js` refuses a truncated record and a flag above 255. spoint's `SnapshotBinFormat` silently accepts a 28-byte record and masks flags, so a byte-for-byte cross-check against spoint only agrees on valid input.
- `src/render` holds only the headless subset of spoint's client/core. spoint's `CascadeShadowSelect.js` patches `THREE.ShaderChunk` at import, and `GroundSample.js` and `PlacementRing.js` import `PlanetFrame.js`, so none of the three is ported.
- `HotReloadQueue` in spoint does not coalesce: it keeps each entry and runs each one. Coalescing is in spoint's HmrRuntime and is keyed by `src/hot/updateKey.js`, which uses url and path for app events, not the app name. A duplicate event therefore reloads once only if the caller uses the coalescer.
- `scripts/fixtures/upstream/ENDPOINTS.md` is upstream's `ENDPOINTS.md` with the project name changed, so no gate compares it to upstream bytes. The doc's header says 62 paths from an `openapi.json` that is not in this repo, but its published, per-game, disabled and manual-only headings sum to 93 with the three published sections totalling 63. The gate checks the 93 and the four headings. It does not reconcile the 62.
- Upstream copies were pinned by sha256 at copy time, before the project-name rename, and the rename changed their bytes. The values are kept here as provenance: ENDPOINTS `ad00d9b6`, CATALOG `1af9ca96`, engine api-b `c72d910b`, reference README `bb4686a2`, reference PATHS `8c7d332d`, tome INDEX `a387aef7`, tome section aggregate `c9b640bb`, skills INDEX `ce4eb971`, skills MANIFEST `0c842ad5`, spawn FINDINGS `4e64f372`, feature-gap report copy `fa101e95` (all sha256 prefixes).
- `World` rests bodies on a ground plane at y = 0, so a body that is at rest sits at y = radius, and a sweep that starts at y = 0 cuts through the ground correction.
- `src/physics-pure/ccd.js` sweeps a body from its pre-step position to its post-step position against each static box, expanded by the radius. The settler applies it only when `boxes` is given, after `world.step()` and before the velocities are read. A body that starts strictly inside the expanded box is pushed to its nearest face, and a body that starts on a face and moves into it is stopped there, because the sweep accepts an entry at t = 0. Without these two cases a body the solver pushes onto a wall face passes through it. The stop is restitution zero (the normal component is removed). The kernel also takes its own `boxes`, resolved after the move, so a thin box in a `World` still needs the sweep.
- `createSettler` reads the body count when it is made and throws on any later change, and its islands are sized to that count. Spawn every body first, then make the settler, and make a new one after each spawn. The settler freezes bodies it has put to sleep, so a `setPosition` on a sleeping body is overwritten.
- `src/kernel/load.js` instantiates the kernel with the plain WebAssembly API and no imports, so `jz` is a build-time dependency only. It reads each buffer from the handle the kernel returns: a BigInt whose high word is `0x7ff98007` for a Float64Array and whose low word is the data offset, with the byte length in the word 8 bytes before the data. It checks the tag and the length and throws on a mismatch, which is how a jz layout change shows. A typed array's `byteOffset` inside jz is 0, as in JavaScript, so the kernel cannot report an address itself.
- `src/kernel/load.js` takes the wasm bytes from the host through `loadKernel(bytes)`. Without them it reads `dist/kernel.wasm` through `process.getBuiltinModule`, which needs Node 22.3 or newer, so a browser never loads `node:fs`. The browser site in `docs/play` is built by `scripts/build-site.mjs` and checked by `scripts/check-site.mjs`. The plan follows the import closure of `World.js` and `settler.js`, and it refuses any Node import and any bare import, so the site carries no vendored package. A static server must serve `kernel.wasm` as `application/wasm`, and `file://` cannot load it.
- GitHub Pages sends no cross-origin isolation headers, so `docs/play` gets them from `site/coi-sw.js`, which re-serves each same-origin response with `Cross-Origin-Embedder-Policy: require-corp` and `Cross-Origin-Opener-Policy: same-origin`. The first load registers it and reloads once on `controllerchange`, so `crossOriginIsolated` is false until that reload. `SharedArrayBuffer` is available only after it, and the worker's headers are not visible to `curl`, which talks to the origin directly.
- `allocateRingBuffer` stamps every control slot empty. Before that, a reader on a fresh buffer read the zeroed slots as player 0 with a zero pose and no stale flag. The writer does not clear slots on construction, so a second writer on a live ring cannot erase its players.
- `TransformRingWriter` refuses a write or release while the ring generation is odd. `readCut` over a locked ring returns `consistent: false` and marks its poses stale.
- `src/transport/wireweaveFraming.js` frames items with big-endian lengths. The gate checks a payload that starts with the batch prefix only when it is sent alone, not when it is joined with others.
- `src/transport/webTransportPolicy.js` uses port 4433 unless a port is given. The error backoff starts at 10 ms, doubles, and stops at 1000 ms.
- `applyMovement` in `src/motion-pure/movement.js` fires a buffered jump only on a tick that carries an input object, as spoint does. A `null` input skips the buffer, so a host that lands with no input object keeps the jump armed until the next input.
- `src/animation/locomotion.js` exports `LAND_DELAY_MS` (500), but no transition reads it. A jump lands on the first grounded tick whose vertical velocity is at or below zero. `settledState` returns null for a NaN speed.
- `src/animation/blend.js` floors the 2D sample distance at 0.01 and gives weight only to the three nearest samples. Without the floor, a query on a sample would take nearly all the weight.
- `checkFreshness` in `src/bundle/freshness.js` reports the first source that is `added`, `changed` or `removed`, and it throws on a missing or duplicate source path. A stamp must be version 1. Content is hashed as given, so a string and its UTF-8 bytes have the same digest.
- The bundle gate in spoint's package.json calls `scripts/bundle-freshness-witness.mjs`, which spoint does not contain. jayzee's `check:bundle-freshness-jayzee` checks its own freshness module and does not check spoint's bundle.
- `defineStatsSystem` and `defineQuestSystem` accept a null `appCtx`. With null, the state logic runs and sends and callbacks are skipped. spoint throws without one.
- The game modules take their clocks as values: `spec.now` for quests and `options.clock` for the event log, each defaulting to `Date.now`. `StatsSystem.addXPResult` calls a closure for the XP curve, so the method still works when destructured.
- spoint's cooldown drift is kept. Ticks of 1.9 and then 0.1 leave a cooldown of 8.3e-17, which still counts as cooling.
- `src/physics-extras/glb.js` refuses index component type 5121, which is unsigned bytes. spoint's `GLBLoader` reads it as uint32, so a copy of spoint would misread the indices.
- `src/physics-extras/glb.js` refuses Draco and Meshopt primitives rather than decoding them. Their decoders are WASM and no Draco fixture exists. A float vertex stride that is not a multiple of 4 is refused in `src/physics-extras/meshopt.js`, where spoint yields NaN.
- The hooks in `src/behaviours/health.js` and `src/behaviours/destructible.js` receive event objects, not `appCtx`, so a host that expects `appCtx` must adapt them.
- `src/behaviours/game-fsm.js` runs `after(ms)` timers from `tick` on an injected clock, not wall-clock timers. Guards and actions also receive the send payload.
- spoint's `findCostCorridor` defaults its budget to `Infinity`, and no 20000 constant exists in spoint's pathfinding sources. The 20000 figure in PARITY row 26 stays unverified until a source documents it.
- `src/terrain-pure/grassDecal.js` reads `Date.now` unless `opts.now` is given. `src/terrain-pure/planetFrame.js` logs through `console.error`, so a host that needs silent terrain has to filter it.
- The marching tables in `src/terrain-pure/marchingCubes.js` and `src/terrain-pure/marchingEdges.js` are copies of spoint's tables. The hot-module-replacement tail of spoint's terrain modules is not ported.
- `LOD_STEP` (7.2) in `src/packages/mapspinner/lod-config.js` is the tessellation step. The split distance is `splitFactor * LOD_STEP` scaled by the viewport term, and `lodDistFactor` does not read `LOD_STEP`, so doubling it puts the terrain one level finer at every distance.
- `publishResolved` in `src/packages/mapspinner/lod-config.js` writes a resolved value into a knob only when the knob is unset or still holds the value it last published. An operator's knob is left alone, so reading a knob and writing it back changes nothing.

- `engine_world_set_awake_budget(n)` caps how many spawned bodies start awake. A spawn past the cap is held: its slot is `kSlotHeld` (4), its body is created and positioned but not added to the physics system, and its pose carries a zero rotation, which `planFrame` skips, so it is neither simulated nor drawn and a ray passes through it. `World::step` adds held bodies awake at the start of each step, in the order of the release view, or in slot order when no view is set, as many as the active count leaves room for, and their pose returns on that tick. Before this a held body was asleep in the world and hung in the air at its spawn point. The cap does not stop Jolt waking a body by contact. `setPosition` and `setVelocity` release a held body, `despawn` frees it without a remove, and `rebase` hides its pose again after the sync. A budget of 0 is no cap, and lifting the cap releases every held body on the next step. `configureWorld` and `scripts/kaggle/bench.mjs` set `TIER_1024.awakeBudget` (4096). The budget bounds the work in a tick; a tick with every body awake costs what it did before. Bodies appear in waves, so the scene settles later. On Kaggle a held body costs the same in or out of the world (run 24: 40960 bodies, mean of ticks 2 to 50 at 4.4 to 4.8 ms out and 4.7 to 5.1 ms in). A budget of 8192 held 40960 with zero ticks over in three repeats and settles by tick 411, but its worst tick was 14.4 ms, so 4096 stays (worst 13.3 ms at a p99 of 6.3 to 9.9 ms); 6144 had 0 to 5 over. `scripts/check-engine-awake-budget.mjs` is the gate.

- A threaded engine instance is never collected unless its mailbox is closed. The knob `reclaim=off` skips the wait. `watchCollected` in `src/engine/memoryReclaim.js` registers its targets with a FinalizationRegistry and allocates and drops a 32 MiB buffer per loop turn until they are collected. That works in Node. In a Chromium worker it does not: 600 nudges over 3.2 s caused 12 major collections and the warm instance was still alive.
- The warm instance of the physics worker runs in a worker of its own (`src/engine/warmWorker.js`), which the physics worker ends as soon as it reports. V8 shares compiled wasm between isolates of one process, so the first tick is the same: 3.9 ms with the warm worker, 4.2 ms warmed in the same worker, 23.6 ms with no warm run. Before this the warm instance was released in the physics worker and its 512 MiB was freed by whichever collection V8 ran next, 7.8 to 15 s into the run: one cppgc sweep task of 40 to 53 ms in the worker, during which the page's main thread sat in `ProxyMain::BeginMainFrame` for up to 44.7 ms. That was the frame interval of 36 to 59 ms at frame 468 in three of six runs, and the 12 to 20 ms in the upload phase at frame 467 before it. `warmRelease=apart|inline|terminate|none` on the render page picks the warm path; `inline` is the old one and shows the sweep, `terminate` never frees the memory and shows none, `none` is the cold control. The page holds 1086 MB with any of them at the end of a run.
- What a slow WebGPU batch is. `scripts/browser/gpuBatch.mjs` splits each `WebGPUDecoderImpl::HandleDawnCommands` batch over 5 ms into its traced steps and the untraced time between them, and the runner samples the GPU process's main thread every 0.5 ms (`scripts/browser/threadSampler.mjs`: run time and run-queue wait from `schedstat`, state, faults and system time from `stat`, and the kernel function it sleeps in from `wchan`, which is readable for a process of the same user). The time is in `Queue::Submit` and in the untraced start of the batch. In both the thread is in the NVIDIA kernel driver: asleep, uninterruptible, in `os_acquire_rwlock_read` or `os_acquire_rwlock_write`, or on the CPU in system time (9 ticks of system time to 1 of user time over the slow steps of one run), with no page fault and no run-queue wait. Chromium makes three submits a frame for the page's one: the other two are its own, at present and at the next texture.
- Who holds that lock. One holder was the witness: `nvidia-smi pmon` once a second gave 17 slow batches in a run, each about 7 ms with 4.5 ms asleep in `os_acquire_rwlock_write`, against 2 in a run without it on a quiet host. The runner now starts it only with `PLANET_GPU_USE=1`. The others are outside the page: with other sessions' browsers on the GPU a run had 10 to 24 slow batches and the same lock waits with no sampler of ours running, and the threads that ran during the waits were this run's Xvfb and another Chromium's GPU process. The page cannot shorten a wait on the driver's lock, so the cause is recorded and the witness names it per interval (next but one line).
- What the unmarked slow ticks are, from the profile rows of Kaggle run 38 (20 rows at 131072 bodies, 4 workers, mean awake tick 7.49 ms against 6.61 ms for the production glue in the same run). In the ticks over budget with no run-queue wait and no involuntary switch, the time is not in one phase. It sits in whichever small loop a thread was in: one `readback rows` job of 13.07 ms (0.2 ms in a quiet tick) while the other three took their usual time; `engine pose export` 7.28 ms (0.66 ms) and `engine readback slots` 6.75 ms (0.44 ms) back to back on the main thread; `IslandBuilder::Finalize` 6.77 ms (0.26 ms); one `SolvePositionConstraints` job of 7.63 ms (1.1 ms). The lost time comes in pieces of about 6.5 to 7 ms on one thread at a time, with no fault, no context switch and no steal time, so the guest kernel counts the thread as running throughout. The ticks follow the wall clock of the kernel run and not the process: `node scripts/kaggle/slowTickClock.mjs build/kaggle/out-v38/results.json` places each tick over 18 ms on the run's clock, and 10 of 15 gaps between consecutive ones are within 0.75 s of a whole multiple of 10 s, where chance gives 15 percent. In the first gate rows the slow tick is at tick 217 to 240 of each process, because a row lasts about 10 s; in later rows of the same configuration it moves to ticks 384, 274, 124 and 50. So something outside the bench runs every 10 s and stops a thread of it for one or two slices. Run 39 confirmed it with a process that has no engine in it (see the canary line below). It is recorded, not fixed, and the gate's medians carry it: run 38 passed with one such tick counted for the candidate and three for the reference.
- The collection of the warm instance is not that cause: the profile rows with `reclaim=off` and the ones that wait for it have the same mean (7.50 and 7.49 ms), and no collection ran in any tick over budget (`gcInTickMs` 0 in every one).
- A frame interval over 25 ms in which the GPU process's main thread slept at least 5 ms, and at least half of the time over one frame period, in the graphics driver lock (`driverLockMs`, state D in a function named `os_acquire_…`), with the page idle and its work within budget, is classified `gpu-driver-lock-in-gap` and, like a host-throttled gap, is not counted against the page when every missed interval of the run is of one of those two kinds. The runner samples the GPU thread unless `PLANET_GPU_THREAD=0`. `check:planet-gap-class` holds the rule.
- A Kaggle run is preceded by a dry run of the same kernel script on this host. `scripts/kaggle/preflight.mjs` packs the plan, then runs `kernel.py` with `JAYZEE_BENCH_DRY=1` against the packed payload: each distinct row once, with its `dryArgs` from `plan.mjs` (4096 bodies, 40 ticks, and the knob `budget=0.01` so that every tick is over budget and the over-budget and profile parts of the result are full), and one row that exists only in the dry run, `pipeProbe.mjs`, which sends a 300 KB result line. It refuses a row with an error, a row whose result lacks a field the gate reads, a run with fewer rows than the plan, and a run in which no line was over the 64 KB of a pipe. `run.mjs` calls it first and uploads nothing when it fails. It takes about 40 s for the regress plan (21 distinct rows). With the defect of Kaggle run 36 put back (`console.log` then `process.exit` in `emit.mjs`) it fails with "unreadable result: Unterminated string". Every bench script sends its result through `emitResult` in `scripts/kaggle/emit.mjs`.
- The kernel records a row it cannot read as an error with the byte count and the tail of the line, and goes on to the next row. Before this one bad row ended the kernel and lost every row after it. Each row carries `startedAtEpochS` and `endedAtEpochS`, the bench carries `loopStartedEpochMs`, and each over-budget tick its own `epochMs`. `results.machine` records the kernel release, the boot command line and the CPU pressure: the Kaggle session runs on a real Linux kernel (6.18, Container-Optimized OS), not on a user-space kernel, with a CPU quota of 4 CPUs per 100 ms.
- What the 10-second stall on Kaggle is, from run 39. `scripts/kaggle/canary.mjs <seconds> <threads>` has no engine and no wasm in it: each thread reads the clock in a loop and records every gap over 1.5 ms with the run-queue wait of that thread. With one thread it saw nothing in two rows of 45 s (widest gap 1.5 and 1.7 ms). With four threads, which fill the four CPUs as the bench does, it had 62 stalls of 4 ms or more, 47 of them within 0.75 s of one phase of a 10 s period on the clock of the kernel run (chance gives 15 percent), every one but one with the wait visible on the run queue. The bench's ticks over budget at 4 workers fall on the same phase: 19 of 22, at 90.07, 100.09, 340.11, 350.04, 420.10, 470.08 s and so on after the kernel started. So the cause is not in the bench process: something in the Kaggle session wakes every 10 s, phase-locked to the start of the kernel, and takes a CPU for 5 to 11 ms, which only a process that fills every CPU notices. `node scripts/kaggle/slowTickClock.mjs <results.json>` prints it as the `LATTICE` line, with the ticks that are off the phase listed by name. In run 39 those were one tick of 18.5 ms with no wait and the two compile ticks of the cold row. In run 38 the same 10 s stall showed with no run-queue wait and no context switch, in pieces of 6.5 to 7 ms, so the session's activity is sometimes a task that displaces a thread and sometimes kernel work that runs on top of one.
- The gate's host rule already leaves out the ticks of that stall that show a run-queue wait and nothing else running in the process (17 of the 22 in run 39). The gate does not use the phase itself to excuse a tick: a rule that drops whatever falls on a 10 s lattice would also drop a regression of ours that happened to land there, and the medians already carry the rest.
- Where the tick goes and what was tried, Kaggle run 40, Xeon class, 131072 bodies, 4096 awake, 4 workers, mean tick while bodies are awake. Before: 7.77 ms (the reference build in the same run). (1) The engine's own serial passes, adopted: the pass over every slot after the readback and the air-layer pass each read one byte per slot, 131072 a tick, and the worker copied the 3.7 MB of pose rows twice. The two passes now test eight slots at a time (`wordAt` in `world.cpp`: a slot needs work only when its state byte is odd, an air byte only when its two flags differ) and the worker copies the rows once, straight from the engine's rows (`engine_pose_header`, `engine_pose_rows`). After: 6.37 ms, quiet-tick p99 9.52 to 8.24 ms, poses bit for bit the same; with all 12288 awake 8.23 to 7.45 ms. In the profile build pose export went from 0.80 to 0.001 ms, the slot pass from 0.44 to 0.11 ms, the air-layer pass from 0.40 to 0.08 ms. (2) Two solver iterations and not four: 5.89 ms, not adopted, because it changes the simulation and with every body awake fewer iterations settled later. (3) The airborne skip off with the 4-step broadphase rebuild kept: 6.07 ms on three repeats against 6.37 ms on five, the same direction as run 33 (6.42 against 6.57 ms); not adopted on that margin, and the first thing to settle next. (4) Worker count: 11.43, 7.49, 7.07, 6.37 and 6.54 ms at 1, 2, 3, 4 and 6 workers, so four stays. What is left in the step, as thread time per tick: finding collisions 7.6 ms over four jobs (about 30 percent of the tick), the position solve 4.9 ms, the velocity solve 1.7 ms, the gravity rows 1.3 ms, the readback rows 0.9 ms.
- The page's frame work at the 1024 tier is 1.44 ms at the median, and 0.98 ms of it is two loops over every body that find nothing to do once the bodies sleep: `planFrame` (0.52 ms, whose culled lists the WebGPU backend no longer draws from) and `uploadBodyRecords` (0.46 ms of compares). The physics worker's tick is 0.27 ms at the median. The warm worker costs 0.5 s at boot and nothing per tick. Chromium makes three submits a frame for the page's one, and the page cannot join them.
- The pose buffer's header carries an epoch (`Header::epoch`, byte 36, where a reserved word was). `World::poseEpoch()` moves it once whenever a pose row was written since it was last read (`sync`, `hide`), and an import takes the epoch of the buffer it applies. On the page three things read it. `createPoseHandoffCore` skips the copy and the import of a buffer whose epoch it has already applied (`handoff.unchanged` counts them). The frame's stamp is the epoch with a digest of the class bytes, and with an unchanged stamp the WebGPU backend skips `uploadBodyRecords` and the frame skips `planProps`, the pass that builds the culled lists; the WebGL2 backend draws from those lists, so it runs the pass every frame. The counters `visible` and `checksum` then belong to the last frame that ran the pass, so `renderer.stats()` calls `engine_render_refresh_props` first. `bodyWork=always` on the render page is the control. Measured on the 1024 page with WebGPU, 900 frames: frame work 1.19 ms at the median with the control and 0.505 ms without it (plan 0.47 to 0.01 ms, upload 0.45 to 0.14 ms), the pass ran in 267 frames and 634 pose buffers were unchanged, and `visible` and `checksum` at the end are the same in both.
- The profile build no longer drops a scope after 64 calls in a tick: it times one call in sixteen of it and scales the time and the count by sixteen (`sampledScopes`, `sampledEvery` in the result), so the tree queries, the body pairs and `engine planet sphere contact` have figures. A sampled figure is an estimate; a scope with few calls is still exact.

## Dependencies and licences

- The package's `dependencies` are `msgpackr` and `ws` only, because those are the only packages the published surface imports: `exports` names one entry point, `src/index.js`, and the surface is that entry and the two bins. Every other package below is a devDependency. A consumer cannot import the modules that use them, since `exports` names no subpath, and with them as dependencies an install of the 676 kB tarball brought about 128 MB. The tarball now holds the 32 source files the surface reaches, `bin/`, `types/` and `dist/kernel.wasm`: 38 kB packed, 129 kB unpacked, 43 files, and a consumer's `node_modules` is 2.7 MB. `check:package-surface` holds this in both directions: a file the surface reaches must be packed, a packed source file must be reached, and `dependencies` must equal the packages the surface imports. A new export, or a new import in the surface, fails it until `files` and `dependencies` in `package.json` follow.
- `npm install --package-lock-only` with npm 10 drops the `libc` fields from the lockfile, and both npm 10 and npm 11 rewrite the wireweave `resolved` URL from `git+https` to `git+ssh`, which CI cannot fetch. Regenerate the lock with npm 11 and put `git+https` back.
- `meshoptimizer` 1.2.0, MIT (`node_modules/meshoptimizer/LICENSE.md`). Pinned exactly to the version spoint locks. `src/packages/streaming-gltf/meshlet-codec.js` loads it with a dynamic import, and `scripts/fixtures/spoint/cluster-lod.json` records the version it was generated with.
- `recast-navigation` 0.43.1, MIT, with `@recast-navigation/core`, `@recast-navigation/generators` and `@recast-navigation/wasm`, all 0.43.1 and MIT. Pinned exactly to the version spoint locks. Its WASM binary ships in `@recast-navigation/wasm`, and `src/pathfinding/recastBake.js` is the only importer.
- `jolt-physics` 1.1.0, MIT (`node_modules/jolt-physics/LICENSE`). Pinned exactly to the version spoint locks. `src/collision/joltHost.js` loads it with `import('jolt-physics/wasm-compat')`, and `src/collision/dormantStatics.js` is the only other module that reads Jolt body state.
- `castRay` in `src/collision/joltHost.js` refuses a ray that reaches a parked static with `unavailable: 'static-colliders-migrating'`, as spoint does. A host's `dormantStatics` is created on first use, so a ray cast before any park costs no dormant check.
- `drain(budgetMs, movers, clock)` in `src/collision/dormantStatics.js` reads its clock from the third argument, defaulting to `performance.now`. spoint reads the global `performance.now` directly, so its generator swaps in the counted clock for each drain call. A budget witness must inject the clock; wall time makes the batch count depend on the machine.
- `PhysicsIntegration` vehicle methods delegate to `physicsWorld.vehicles`, so the physics world must expose a vehicle backend (the Jolt host does). Without one they throw a TypeError naming the backend, rather than returning a null that a caller might read as a refused build.
- Overlap queries in `src/collision/joltHost.js` read each hit through `CollideShapeCollectorJS` and `J.wrapPointer(ptr, J.CollideShapeResult).get_mBodyID2()`, and the collector needs a no-op `OnBody`. `CollideShapeBodyCollectorJS.AddHit` gets a pointer whose contents are not a BodyID (the same pointer, different bytes per hit), so it cannot give ids.
- three 0.185.1, MIT (node_modules/three/LICENSE). Pinned exactly to the version spoint locks. src/vat/vatBake.js is its only importer in jayzee, and bakeVAT needs no GL context: it drives an AnimationMixer and writes matrices into Float32Array texels.
- `@three.ez/instanced-mesh` 0.3.16, MIT (`node_modules/@three.ez/instanced-mesh/LICENSE`). Pinned exactly to the version spoint's lock resolves (its package.json has `^0.3.15`). `src/client/playerVatRenderer.js` is its only importer in jayzee.
- `engine/src/futex_clockfree.cpp` replaces emscripten's `emscripten_futex_wait` in threaded builds. The library version reads the clock import on every main-thread loop, and that import allocates per call. The replacement spins with a bounded count for timed waits and reads no clock.
